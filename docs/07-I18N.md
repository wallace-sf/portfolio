# 07 — Internationalization (i18n)

> UI translations, domain content localization, and locale routing.

---

## Supported Locales

| Locale | Language | Role |
|--------|----------|------|
| `en-US` | English | `defaultLocale` |
| `pt-BR` | Brazilian Portuguese | Required for all domain content |
| `es` | Spanish | Optional, falls back to `pt-BR` |

Defined in `apps/site/src/i18n/routing.ts`:

```typescript
locales: ['en-US', 'es', 'pt-BR'],
defaultLocale: 'en-US',
```

---

## UI i18n — `next-intl`

**Configuration:**
- Routing: `src/i18n/routing.ts` — `defineRouting`, `createNavigation`
- Server: `src/i18n/request.ts` — `getRequestConfig`, loads `messages/{locale}.json`
- Middleware: `src/middleware.ts` — locale detection and routing

**Usage in components:**

```typescript
import { useTranslations } from 'next-intl';

const t = useTranslations('Home');
t('projects_title');
```

**Adding UI translations:**
1. Edit `messages/{pt-BR,en-US,es}.json`
2. Keep the same keys across files (rely on `defaultLocale` fallback for missing keys)
3. Use `useTranslations('Namespace')` and `t('key')` in components

## Blog i18n

The blog is served by `apps/site`, so it shares that app's single `next-intl`
setup — one `routing.ts`, one `request.ts`, one middleware. There is no
cross-zone locale coordination.

- **UI chrome strings** live in the `Blog` namespace of `messages/{locale}.json`
  (`title`, `subtitle`, `empty`, `newerPost`, `olderPost`, `postNavigation`, …).
  Route/metadata strings live under `Metadata.BlogPage`.
- **Post content** — **MVP:** MDX-in-Git, one file per locale
  (`content/posts/<slug>/<locale>.mdx`), read by `FileSystemBlogPostRepository`,
  all three locales required per post. **Blog v2 (planned):** post content moves
  to Postgres `Json` localized columns (Option A, below) — `title` /
  `description` / `content` each hold `{ "en-US": "...", "pt-BR": "...", "es": "..." }`,
  with `content` holding an MDX string per locale. Same persistence strategy as
  portfolio domain content. Either way the repository builds `BlogPost.title` /
  `.description` / `.content` as `LocalizedText` and use cases resolve one locale
  with `.get(locale)` when building DTOs. See
  [blog-v2-phase-0-design](./superpowers/specs/2026-09-01-blog-v2-phase-0-design.md).
- **URLs** are locale-first: `/<locale>/blog`, `/<locale>/blog/<slug>` (v2:
  `/<locale>/blog/<year>/<month>/<slug>`). Switching locale on a blog page
  preserves the path after `/<locale>`.

## Domain Error Messages

Domain errors use **stable codes** (`INVALID_SLUG`, `ERROR_INVALID_ID`, etc.). The edge resolves a localized message:

- **Source**: `ERROR_MESSAGE` in `@repo/core/shared/i18n/` (`pt-BR`, `en-US`)
- **Rule**: the domain never chooses a locale — callers (web / API) resolve translated messages from `ERROR_MESSAGE` using the request locale
- **`es`**: not yet in `ERROR_MESSAGE`; extend when added

**Adding domain error messages:**
1. Add the code to `ERROR_MESSAGE` in `@repo/core` for `pt-BR` and `en-US`
2. Ensure edge-level mapping reads from `ERROR_MESSAGE[locale][code]`

## Domain Content — `LocalizedText`

For multilingual content (project titles, experience descriptions, etc.), the domain uses `LocalizedText`:

```typescript
// pt-BR is required; en-US and es are optional
LocalizedText.create({ 'pt-BR': 'Meu Projeto', 'en-US': 'My Project' })

// Retrieving content for a locale (with fallback)
text.get('en-US', 'pt-BR') // falls back to pt-BR if en-US is absent
```

**Current persistence strategy (Option A):** domain content is stored as JSON columns in Postgres. Each column holds a `{ "pt-BR": "...", "en-US": "..." }` object. Prisma returns it as a JSON value; the infra mapper casts it to `ILocalizedTextInput` and passes it to `LocalizedText.create()`. Use cases resolve a single string with `.get(locale)` when building DTOs:

```typescript
title: project.title.get(locale),      // "My Project" or "Meu Projeto"
caption: project.caption.get(locale),
```

---

## Fallback Chain

1. Requested locale → 2. `defaultLocale` (`en-US`) → 3. `pt-BR` → 4. any available value
